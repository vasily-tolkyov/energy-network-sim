# PLAN-009 · 多步目标链规划核心：设计与验收

**基线**：`energy-network-sim @ 33f8b6a`（第二轮复审修复后的最新 main）。
**前置状态**：预测核心（R1/R2A/R2B/R3）与行为核心（自主探索、纠错、概念自形成）已验收通过。本文档定义第三套核心——**规划核心**——的设计、接口与验收。全部判定性知识（状态转移）由模拟神经网络经验学习承担；规划控制流（候选枚举、rollout 循环、循环检测、重规划触发）属于允许程序化的方法先验，与探索器同级。

## 1. 目标与非目标

**目标**：在只学过单步转移经验的条件下，规划核心能对"从状态 S 到目标 G"输出可执行的动作序列，并在执行偏离预期时检测失配、重新规划。

**非目标**（本轮不做，不得顺手实现）：
- 不要求严格最短路径；步数仅与 BFS 参考值并列表报（BFS 只存在于测试评分侧）。
- 不做连续状态插值的规划；规划世界全部离散化到感受野编码。
- 不改预测核心、探索器的任何既有语义。
- 不做开放世界/分层规划。

## 2. 不变量（承接 §0，新增第 9–12 条）

1. 两段绑定：条件↔核、核↔结果按通道各一段，绝不三者同集合。
2. 只有带结果证据的核进预测候选；空结果 `{}` 写入被拒绝（第二轮起抛错）。
3. 容量边界显式抛错；点火不等式在构造期检查（不可行配置直接拒绝）。
4. 能量账本只记保守部分（W/Γ/θ），DI 不进 `energy()`。
5. 教师真值只用于实验台应答与评分，**不进学习核、不进规划器决策**。
6. 证据优先级：observation > hypothesis；hypothesis 永不否决 observation；冲突记日志不静默。
7. 编码层等价关系全工程唯一（`compatibleSupports` / `sameSupport`），冲突判定不在别处另写。
8. 指标口径：答案质量与动力学质量分列；如实歧义不逼单选；失败样例落盘保留。
9. **（新）规划 rollout 全程只读**（规划阶段冻结学习，§3.4）；若将来引入写入式模拟，全部模拟写入必须走 hypothesis 通道（证据优先级第 6 条），不得依赖"假设覆盖观察"做反事实。
10. **（新）预测的非收敛/终止状态沿规划链全链穿透**；`no-quiet-candidate` 语义 = 该动作在此状态不可行。
11. **（新）执行监控用 `ForecastSnapshot`（值快照+代际），不得只缓存核索引**——共享记忆后续学习会改变核语义。
12. **（新）否决资格与加分幅度已解耦**：消融配置按真 2×2（gain 控 W、veto 控 Γ）设定，"gain=0 保留否决"是预期行为。

## 3. 架构

### 3.1 组成

```
规划核心 = 转移经验记忆（FieldRuleMemory 一份）
         + 规划器（程序化：候选动作枚举 + 正向 rollout + 循环检测 + 重规划）
         + 执行监控（captureClassify + ForecastSnapshot）
```

- **转移经验记忆**：`FieldRuleMemory`，条件维 = 状态维 + 动作维，结果维 = 下一状态维。离散世界把档位值直接映射到对应感受野量程。选 FieldRuleMemory 而非 PopRuleMemory 的理由：原生支持联合捕获与 `ForecastSnapshot`，且第二轮证据语义（evidence.ts）在两侧一致。
- **规划器（程序化，允许）**：给定当前状态与目标状态，做**正向 rollout**：每步枚举候选动作 → 以 `(状态, 动作)` 为条件钳制调用 `predict` → 读出预测的下一状态 → 前进。深度上限 = 2× 状态空间直径；访问集（状态签名）防循环。选择正向展开而非目标反向链接的理由：链式生成的物理方向与经验写入方向一致（A→B 的有向通道正向可燃、反向受阻），反向链接需要额外的逆向推断机制，超出本轮范围。
- **执行监控**：每执行一个动作，把实际观察到的下一状态与预测快照送 `captureClassify`；`class !== "within-envelope"` 即触发重规划（以当前实际状态为新起点）。

### 3.2 关键接口（按 33f8b6a 实际签名，不得凭旧文档臆测）

```ts
// 转移经验记忆（src/pop/concept/field-memory.ts）
const mem = new FieldRuleMemory(encoder, new EmergentMap([], encoder), { maxRules });
mem.setOutcomeDimensions(["nextPos", ...]);
mem.learnFromObservation(conditions, outcomes, repeats);          // 真实观察写入（唯一写入口）
// 注意：FieldRuleMemory 没有 learnFromQuery；本轮规划 rollout 全程只读（§3.4），
// 不需要假设写入。若将来引入写入式模拟，须先按同一证据语义（hypothesis 源、
// 不得否决 observation）为 FieldRuleMemory 补该接口，再使用。
const p: FieldPrediction = mem.predict(conditions, seed);
//   p.values / p.ambiguous / p.winningCores / p.converged / p.terminationReason
//   terminationReason ∈ "fixed-point" | "flip-budget" | "quiet-constraint" | "no-quiet-candidate"

// 执行监控（src/pop/attention/capture.ts）
const snap: ForecastSnapshot = { coreIdx: p.winningCores[0] ?? null, values: p.values,
  generation: mem.evidenceGeneration, converged: p.converged, terminationReason: p.terminationReason };
const cap = captureClassify(mem, conditions, observedOutcomes, snap, seed);
//   cap.class ∈ "within-envelope" | "prediction-violation" | "unknown-change"
```

带池电路的求解调用（记忆内部已封装，规划器不得绕过）必须保持：`fallbackQuietOnly: true`、`quenchCandidatesOnly: true`、`quenchMaxFlips = 8N`。

### 3.3 rollout 步进判定规则（第二轮契约的直接应用）

对每一步 `predict` 的返回，按此优先级判定：

| 情形 | 判定 |
|---|---|
| `terminationReason === "no-quiet-candidate"` | 该动作在当前状态**不可行**，从候选中剔除 |
| `values` 全 null 或任一维 ambiguous | 该动作结果未知/歧义，标记为"未探明"，不优先选择但不判死刑 |
| `converged === false` 且读出有值 | **可用但标记**：计入"近似步数"统计，链照常前进 |
| 正常收敛有值 | 可用 |

**链合法性判据（验收口径，先定死）**：一条规划链成立当且仅当执行后到达目标；报告时分列①链到达率（答案质量）②全链 fixed-point 步占比（动力学质量）。**不要求**全链每步收敛作为通过条件——带池电路下非收敛返回是常态（基准实测 74–90% quiet-constraint），把收敛当通过条件会人为压低通过率。

### 3.4 候选动作排序

每步按序优先：①已观察转移中预测指向未访问状态的动作；②预测值收敛的动作；③未探明动作；④指向已访问状态的动作（防循环兜底）。同序内按动作编号稳定排序，不引入额外启发打分。规划全程**冻结学习**（只读记忆），执行阶段的真实观察才写回。

## 4. 世界 A：一维路径世界（正向对照）

**世界定义**（本地草稿 `src/topics/path-world.ts` 可作参考，但以本节为准重写并纳入版本管理）：

- 状态：位置 `pos ∈ {0..7}`；动作：`move ∈ {0=左, 1=右}`；端点处原地不动。
- 真值：`nextPos = clamp(pos ± 1, 0, 7)`，只存在于实验台与评分侧。
- `PathBench.conduct(state, action) → { nextPos }`，每次调用计 1 成本；非法状态/动作抛错。

**学习阶段**：探索器（可复用 `Explorer` 的语料模式）在 PathBench 上自主收集转移经验，预算声明（上限如 64 次 = 8 状态 × 2 动作 × 4 重复），终止原因如实记录（`quorum-met` 是启发式停止，不是完备证书）。

**规划阶段**（冻结学习）：随机抽 `(start, goal)` 对，规划器输出动作序列；测试侧用 PathBench 逐步执行验证。

**指标**：
- 可达率：规划链实际到达 goal 的比例（主指标）。
- 步数分布：与 BFS 参考步数的比值分布（参考指标，不要求 1.0）。
- 规划成本：每次规划的 predict 调用次数；执行阶段的重规划次数。
- 动力学质量：全链 fixed-point 步占比；`no-quiet-candidate` 出现次数。

## 5. 世界 B：有序链 + 单向门 + 重规划（核心验收）

**世界定义**：

- 状态：节点 `node ∈ {A,B,C,D,E}` 的离散链（编码为单维 5 档）；动作：`advance ∈ {0=尝试前进, 1=停留}`。
- 转移真值（仅实验台持有）：A→B→C→D→E 单向前进；**单向门**：C→D 可通、D→C 不可回（停留动作原地不动）；E 为吸收态。
- 目标：从 A 到 E。顺序约束：必须经过 B、C、D 的顺序，不得跳跃（真值本身保证无跳跃边）。

**注入案例（重规划验收，两个都必须做）**：
- **注入 1（通道阻断）**：规划完成并开始执行后，在到达 C 时由测试侧把 C→D 单向门改为关闭（真值改为 C 停留）。期望：执行监控在 C 处捕获 `prediction-violation` 或 `unknown-change` → 触发重规划 → 新链应停留在 C 或报告不可达（**如实报告不可达也算成功**），不得输出穿墙的假链。
- **注入 2（状态扰动）**：执行到 B 时由测试侧把实际状态强制置为 D（绕过 C）。期望：监控检测到实际状态 ≠ 预测快照 → 以 D 为新起点重规划 → 到达 E。

**指标**：顺序正确率（链中节点次序合法的比例）、单向门避让率（不输出 D→C 方向动作的链占比）、两个注入案例的重规划成功率、每次重规划的 predict 增量成本。

## 6. 消融与对照（按真 2×2）

- 规划核心本体不做机制消融（无新机制）；**必须含两个基线对照**：
  - 随机动作基线：同预算随机选动作的执行到达率。
  - 无重规划对照：注入案例下不重规划（链执行到底）的失败率，用于证明监控—重规划链路的价值。
- 若报告"假设写入不污染经验"的隔离性证据：rollout 模拟前后对已确认经验做读回断言（第二轮证据语义的直接复用）。

## 8. 测试计划与工程纪律

1. **环境**：Node ≥24；`npm ci && npm run build && npm test`；全量 `npm run verify`。
2. **种子**：`SEEDS` 环境变量分段（如 1,2,3），逐种子落盘到 `runs/plan-*.log` / `runs/plan-*.json`；每条规划链记录：起点、目标、动作序列、每步 predict 的 `converged`/`terminationReason`、执行观察、捕获分类、重规划事件。
3. **数字纪律**：通过线按本节锁定，不得按单次结果回调；失败样例（错序、穿墙、未达）原样保留进 JSON，不得删断言凑绿。
4. **最小改动**：不动预测核心、探索器、评审修复的任何文件，除非发现新缺陷（发现则先报告再改）。本地未跟踪草稿 `src/topics/path-world.ts` 是实现参考，最终以本文档重写并提交为准。
5. **提交**：世界 A、世界 B、消融与文档各自独立 commit；最终推送前工作区干净。
6. **文档**：完成后在 `docs/` 新增评估文档，数字按实测锁定并注释实测值；明确声明：规划控制流是程序化方法先验，神经化的是全部转移知识与逐步预测。

## 9. 复杂度与资源预估（本机）

- 世界 A/B 网络规模 N 为数百神经元级；单次 predict 实测均时参考化学基准 ≈28ms（更大网络），规划世界应显著低于此。
- 单次规划成本上界 = 深度上限 × 候选动作数 × 单 predict 耗时；世界 A ≈ 16×2=32 次 predict，世界 B ≈ 10×2=20 次，秒级内完成。
- 无需 GPU；内存可忽略。若实测显著超此预估，先查是否误用了全局退火或漏传候选约束。
