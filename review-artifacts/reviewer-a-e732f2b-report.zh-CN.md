## 1. 结论

**修复有实质效果，上一轮多项核心反例已经消除；但尚不足以认定核心正确性问题已经闭合。新增纠错机制引入了可复现回归，静息态回退契约仍有漏洞，连续 R2 的变化检测存在方向依赖。建议继续作为研究原型使用，暂不通过核心正确性与持续学习可靠性的验收。**

三类结果必须分开：

- **确实修好的部分**：DI 保守能量账本、非收敛显式标记、常规容量溢出保护、先侧重后观察的注册、灭灯亮度评分、无变化结果的错误归因、README 示例及若干过强声明。
- **通过改变声明解决的部分**：不再保证有限退火全局最优；焦点选择明确包含程序化读出；不再将 0.5 输入簇等同精确门限发现。旧反例仍成立，不代表新契约继续违约。
- **仍然阻碍验收的部分**：相近连续观察可把自己的结果场全部否决；自写猜测能覆盖已确认真值；“只选静息驱动态”回退仍可能返回驱动介入状态；R2 对同一对输入正反向给出不同的变化判断。输入验证与消融设计也未完全闭合。

测试总览：仓库自有 **113/113 通过**；上一轮 20 项原样重跑 **15 通过、5 失败**；本轮新建 **20 项测试，7 通过、13 失败**。失败数不是独立缺陷数，更不是对随机输入的失败率。四个纠错/连续编码序列用例在旧提交上 **4/4 通过**、新提交上 **0/4 通过**；另外 R2 方向对照在旧版通过、新版失败，合计五个用例提供直接回归证据。

本轮完成官方离散/连续三个种子、更新/冻结扩展、六个配套入口，以及五组独立训练与评分；逐条复核 **1,972 条预测记录**，对应 **1,052 个不同输入条件**（区分离散/连续；含跨种子复测，不宣称这些样本相互统计独立）。固定旧随机探针上的连续 seed 4 粗粒度从上轮 **12.5%** 提升到 **78.9%**。完整数值、覆盖率、基线与非收敛统计见第 5–6 节。预测提升与学习序列正确性是不同验收项，不能互相替代。

## 2. 范围、方法与边界

从 f25fefe 到本次提交共变更 53 个文件，约 1,758 行新增、648 行删除。审查覆盖共享动力学引擎、DI 和回退、规则注册与纠错、场编码、R2、探索停止及证据写入、概念更新、焦点/注意力、评分与文档。测试顺序与原始结果都有日志。

运行环境为 Windows 11、Intel i7-10875H（8 核/16 线程）、约 15.9 GiB 内存、Node.js 24.14.0、npm 11.9.0；具体机器记录见 `environment.json`。使用锁文件 `npm ci`，随后 `npm run verify`。多个原生实验进程并行执行，因此墙钟耗时不作为隔离性能基准或能耗证据。

通过 npm 官方 registry 重新执行的依赖审计报告已知漏洞为 0（`npm-audit.json`）。它仅覆盖依赖漏洞库，不覆盖本文逻辑问题。仓库未见 `.github/workflows` 自动验证配置，新增回归集仍需要纳入持续集成并覆盖本轮序列缺陷。

本次独立验证分为四层：

1. **原样回归**：复制上一轮 20 项脚本和全局最优反例，不改其断言，核对作者对旧报告的回应。
2. **新契约与新反例**：建立 `revision-tests.mjs`，既验证修好的机制，也检查新纠错、回退和边界行为。
3. **同数据对照**：原始独立 harness 对种子 4/5 重跑，保留旧探针种子 `20260919`，检验作者声称的改进。
4. **新数据验证**：新种子 6/7，均匀随机探针 PRNG 改为 `20260920`，未调整学习参数；评分前先完成探索，评分真值不进入学习。最近邻使用相同全部观察、所有条件维等权、归一化 L1 距离，平局取最早观察。没有把真实因素名单交给基线。

新增动力学检查只读取最终状态、能量、残余可翻转量与驱动是否静息，不改变权重、状态翻转或随机数。新 harness 对 DI 源缓存的读取至多影响计算缓存，不影响网络规律。旧 harness 的 `maxQuenchFlips` 字段沿用旧名，而新版本 `trace.flipCount` 已变为退火与淬火的**总翻转数**；不能把该字段直接当成淬火超预算证据。

没有发现运行时 LLM 或外部 AI 服务依赖，也没有发现当前学习核心直接调用教师真值函数预测。此结论不等于无算法先验：变量、范围、候选网格、差分方法、阈值、结果容差和停止规则仍由程序给定。

历史冻结 runner `proto`、`proto:plant`、`exp:layers`、旧 `exp:attention`、`exp:capacity`、`exp:scale` 未再逐一完整重跑；相关自动化测试已经运行。报告不把作者的历史/本次自测日志冒充本机独立结果，也不把本次审查当作安全认证、硬件能效证明或开放多步任务验收。

### N01 · P1：连续纠错否决压灭新旧结果的共同感受野

位置：[src/pop/concept/field-memory.ts:445](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/concept/field-memory.ts#L445)、[src/pop/concept/field-memory.ts:453](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/concept/field-memory.ts#L453)、[src/pop/concept/field-memory.ts:484](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/concept/field-memory.ts#L484)。

`vetoSupersededOutcomes` 用原始实数是否变化（>1e−9）决定“旧结果需要被否决”，随后对旧值的**全部**感受野写 Γ=3.0。连续相邻值可能共享大部分乃至全部神经元；这些神经元同时代表新观察。当前实现没有排除新旧交集。

R07 中 0.50 和 0.51 的编码相同；加强新结果的 W 上限只有 0.6，紧接着同一核心对整片相同结果场写抑制。最终 core 激活、结果全空，且 `converged=true`。R08 用固定、无噪声函数 y=x+0.3：输入 0.20→输出 0.50，输入 0.21→输出 0.51。两个不同输入共享条件编码，第二次写入触发同一根因，两条正确经验均无法读回。**这里没有真值随时间反转，不能归入修复说明排除的非平稳世界。**

旧提交对这两个用例都读出 0.5，是合理的有限分辨率近似；新提交均读空。因此这是修复引入的回归。另一个诊断例 .50→.525 将结果偏移到单个残余场中心 .6125，说明不只是完全相同编码的问题。

建议：按编码支持区和证据兼容性判断替换；至少只否决旧结果独有区域，不能对交集一刀切。更根本地，应为同条件编码中无法区分但数值略异的真实观察定义聚合、不确定性或细分规则，而非把量化别名当成反证。先加入相同/部分重叠/不相交感受野的三组序列回归，再复跑全部连续学习实验。

### N02 · P1：自写猜测拥有与真实观察相同的否决权，能永久破坏已知真值

位置：[src/pop/popmemory.ts:172](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/popmemory.ts#L172)、[src/pop/popmemory.ts:407](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/popmemory.ts#L407)、[src/pop/popmemory.ts:426](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/popmemory.ts#L426)、[src/pop/popmemory.ts:468](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/popmemory.ts#L468)。

新的 `coreLastOutcome` 没有记录来源。`learnFromQuery` 与 `learnFromObservation` 都调用同一个 superseded-outcome 否决方法，写强度 3.0 的旧结果抑制。原来“观察上限 0.6、自猜上限 0.4”的优先级因抑制边而被绕过。

R05：观察 y=0 并确认能读回 0，写一次错误自猜 y=1 后读回 1。R06：再观察真实 y=0，会把 y=1 也否决；旧的 y=0 抑制没有撤销，最终两个结果均不点燃，返回 null。重复观察的真值一直是 0，世界没有变。

旧提交 R05/R06 均通过；新提交均失败。R18“先错猜、后第一次正确观察”仍通过，说明已有回归测试只覆盖了单向纠错，漏掉观察已经存在时的路径。

建议：保存观察/推测的来源和证据强度；猜测不能否决已确认观察。真实纠错须定义对既有否决的撤销、衰减或版本化，而不是永久双向累加。当前自主探索主要写观察，不能据此宣称所有官方探索分数都受本缺陷影响；它直接影响公共响应学习 API 和允许查询参与学习的管线。

### N03 · P1：fallbackQuietOnly 只过滤候选更新，没有保证最终回退候选合法

位置：[src/network.ts:485](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/network.ts#L485)、[src/network.ts:492](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/network.ts#L492)、[src/network.ts:503](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/network.ts#L503)、[src/network.ts:525](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/network.ts#L525)、[src/network.ts:535](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/network.ts#L535)。

算法只在更新 bestState 时检查驱动是否静息；退火结束却仅在 bestEnergy < currentEnergy 时恢复它。若退火末态由 DI 驱动、保守 E 比所有合法静息态更低，算法保留这个不合法末态。接着淬火 bestState 直接从它初始化，未验证资格；所有合法静息态 E 更高，就永远无法取代该初值。

R04 的三节点网络 θ=1.5、W01=W12=2、DI(2→1)=4，输入 0。已访问的合法静息态 {0} 的 E=1.5。使用 `fallbackQuietOnly:true`、1 层×1 扫描、温度 1e−9、淬火预算 8，最终返回 {0,1,2}、E=0.5，DI 源 2 活跃。它如实报告不收敛，但违反新选项的候选资格契约。总翻转数 10=退火 2+淬火 8；这里不是预算超限，也不是能量账本失配。

新种子 6 的真实训练中同样出现该路径（量化结果见第 6 节）。这使它超出了仅对人为特殊参数有效的边界例子。

建议：维护“存在合法候选”的独立标志，非法态不能作为任何阶段的默认最优值；阶段转换时携带合法候选，不能重新以任意末态初始化。若没有合法候选，应明确返回失败原因。修复后的有限预算预测需要重新评分。

### N04 · P1：场级 R2 对换实验顺序会改变是否发现因素

位置：[src/pop/r2pop.ts:155](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/r2pop.ts#L155)、[src/pop/r2pop.ts:171](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/r2pop.ts#L171)。

场级差分只遍历 meanB 的通道，计算 mb−(meanA??0)。当新结果的感受野是旧结果的子集，只有 A 独有成员，B 独有集合为空，该通道就从 outcomeDelta 消失。随后 `outcomeChanged` 由这个空对象推导成 false。

R19 通过真实 `ConceptFormation → EmergentMap → EmergentChannelAdapter` 构造 x 两档、y 连续场。y=0→0.05：报告 delta=0.125、有变化、影响因素 x；交换同一对经验，y=0.05→0：报告 delta={}、无变化、无因素，且两向都 `undecidable=false`。不能把这个方向差异解释为未知状态或随机种子。

旧版同一 R19 用例通过，两向 delta 为 ±0.025，均识别因素 x。只遍历 meanB 的代码早已存在，但这次分层阈值及 outcomeChanged 判据改变后，潜在的单侧缺失问题变成实际的因素发现回归。不能把它仅描述成没有变化的历史问题。

建议：覆盖 A/B 通道并集，明确只有单侧差分时如何恢复带符号的物理/编码变化。至少保证交换两经验时变化判定和因素集合不变、幅度符号取反。R14 证明本次对恒定结果的修复有效，但它没有覆盖本问题。

### N07 · P2：所谓 2×2 消融仍缺少“无正向侧重、有否决”一格

位置：[src/pop/popmemory.ts:259](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/popmemory.ts#L259)、[src/pop/concept/field-memory.ts:295](https://github.com/vasily-tolkyov/energy-network-sim/blob/e732f2b4ef46e0ac482480095a31cb5aa23ec6be/src/pop/concept/field-memory.ts#L295)、`src/pop/runner-pop.ts`、`src/topics/runner-chem-pop.ts`。

## 9. 文档和实验治理仍有的问题

**当前仓库内部存在多套数字。** 更新后的审核指南仍写 95 项测试和旧 A/B 数字；README 连续段落仍写 117 次、84.2%/97.5%，并保留旧的 A/B 成本 +48% 解释，而修复说明给出另一套数值。修复说明连续 79/84/132 次的均值是 98.33，称“98 次”属于取整，应明确。README 的新概念 3.94/第 5–6 次形成与本提交扩展日志也不一致。旧数字应标注对应历史 SHA，不能与“最终代码、日志绑定本提交”的表述混用。

容量基准本次确实达到两种结构的 taught 全 E 档 100%，是应当承认的进步；“与修复前一致”却不准确：上一轮原始日志的 mod-8 E=8/E=24 与平滑 E=8 并非 100%。E=64 时 heldout 样本数为零，却仍显示 0.0%；应改为 N/A。本报告不把这个 0.0% 当成泛化失败。

**声明收窄不完整。** README 已承认有限预算近似，但前一句仍写“精确 C 内能耗极小”；`network.ts` 的大段说明仍含“结构性冻结”“保证局部极小”“重新严格单调下降”等无 DI/全网淬火前提不清的旧句。审核指南仍宣称全部智能来自少数规律，与新先验清单并存。应统一有效契约，避免让使用者自行裁决冲突文本。

**旧评审数据已成为修复开发集。** 作者明确用 seed 4/5 harness 进行复核和调试，不能再将其称为完全未接触的最终泛化集。因此本次保留同数据复现，同时增加 seed 6/7 与不同均匀探针序列；这仍只覆盖少量种子、同一函数族，没有证明未知物理规律或跨领域一般化。

**改善归因不能只归于单项机制。** 离散 quorum 从 8 调到 16、加入端点覆盖门、所有实验写观察、调整写入强度和回退同时发生变化；新旧准确率提升是整个提交的效果。没有逐因素受控实验，不能把全部增益独占归于某一修复。扩展更新/冻结实验仍有不同观察预算，不能单靠准确率判定概念更新更优或更差。

**持续性和长期工程目标仍未证实。** 固定稠密矩阵、固定容量、全历史配对/重放、缺少模型快照恢复和淘汰策略仍存在。连续 Explorer 容量固定 192，而可配置实验预算默认 300、扩展 400；改为每次实验都写观察后更应提供明确容量策略。代码先 conduct 再 learn，再 register，若 learn 因容量/校验失败，付费观察尚未进入 planner 日志。该后果来自源码顺序，本次不把它冒充已完整跑到第 193 个唯一核的端到端实验。

注意力缓存目前主要保存核心索引而非不可变预测值/模型版本；共享记忆可能在后续帧中改变同一核心含义。新时序安排是进步，但若要证明严格的“事前预测”，还应持久记录生成时结果及版本，并以它评分，而不只记录可变记忆中的引用。这里属于设计风险，本次没有为其宣称新的独立性能损失幅度。
